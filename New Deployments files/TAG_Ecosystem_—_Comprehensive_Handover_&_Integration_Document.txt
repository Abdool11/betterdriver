2. What Was Built in This Session
2.1 Auth UX - All Platforms
Problem: Login pages had no password visibility toggle, and the BD driver portal logout button was wired to a route that did not exist.

What was built:
• Password show/hide toggle added to all four login pages (GFA admin, GFA client, BD admin, BD driver)
• Missing BD driver logout API route created at app/api/auth/logout/route.ts

No database changes required.



2.2 TCO Optimizer Mixing Desk - TAG
Problem: The TCO Calculator showed the summary card first, then the charts below - users had to scroll past the results to reach the inputs.

What was built:
• New layout: Cumulative Cost Over Time graphs at the top (always visible)
• New TCO Optimizer card below the graphs - a dual-sided "mixing desk" of sliders:
◦ Left side (Diesel): Monthly km, Vehicle life, Vehicle price, Finance rate, Diesel price
◦ Right side (Electric): Monthly km, Vehicle life, Vehicle price, Finance rate, Electricity price
◦ Monthly km and Vehicle life are fully independent between Diesel and Electric (charging windows affect available driving hours)
◦ Moving any slider instantly updates both graphs and the summary card
• TCO Summary card moved to the bottom
• Second chart added: annual saving bar chart (green = electric ahead, amber = diesel ahead)

No database changes required.



2.3 Certificate Auto-Generation - BD
Problem: The certificate system was fully mocked. No PDF was generated, no record was inserted on completion, and the registry was empty.

What was built:

A. Auto-insert on programme completion When Moodle fires the completion webhook, the BD webhook route now automatically inserts a row into the certifications table. This happens whether or not the driver ever downloads their certificate. Certificate numbers follow the format BD-YYYYMMDD-XXXXXXXX.

B. PDF download API GET /api/certificate/download generates a PDF on the fly using pdf-lib. It loads the active certificate template from Supabase Storage (or falls back to the default background at public/templates/certificate-bg.png) and overlays:
• Driver full name
• Programme name
• Issue date
• Certificate number

C. Certificate Template Manager (GFA Admin) A new admin page at /admin/certificate-template allows you to:
• Upload a new certificate background (PNG or JPG - design it in Canva, Illustrator, or any tool)
• Set text overlay coordinates (so the driver name, programme, date, and cert number land in the right position on your design)
• Activate or deactivate templates (stage a new design before going live)

D. Public verification page /verify/[certNumber] is a public page that shows a green "Verified" card, amber "Not Found" card, or red "Revoked" card. This URL is embedded in the PDF certificate as a QR code destination and can be shared directly with employers.



2.4 Survey Admin - GFA
Problem: Pre-course and post-course survey questions were hardcoded in the frontend. There was no way to add, edit, or reorder questions without a code deployment.

What was built: A full Survey Admin interface at /admin/surveys with:
• Pre-course and Post-course tabs
• Add, edit, and delete questions
• Three question types: Multiple Choice, Scale (1-5), Free Text
• Bilingual fields: English and IsiZulu for every question
• Activate/deactivate per survey (so you can stage changes before going live)
• Drag-to-reorder questions



2.5 Live Certificate Registry - BD and GFA
Problem: The BD registry was showing mock data. The GFA registry was wired to query Moodle directly - the wrong source of truth.

What was built:

BD:
• GET /api/registry?q=&page=&limit= - public Supabase query on certifications joined to drivers. Supports search by name, ID number, or certificate number. Partial ID masking (last 4 digits visible only). Paginated.
• /registry page rewritten as a live client component with debounced search, loading skeletons, empty state, and pagination.
• /verify/[certNumber] public page for employer and auditor verification.

GFA:
• /registry now queries the BD Supabase API (NEXT_PUBLIC_BD_API_BASE_URL/api/registry) instead of Moodle. Both registries now show the same live data from the same source of truth.

4. SQL Migrations
Run these SQL scripts in the Supabase SQL editor before deploying any of the new branches. All statements use IF NOT EXISTS or ON CONFLICT DO NOTHING - they are safe to re-run.

4.1 Certificate System
-- Certificate template settings (stores active template URL and text positions)
CREATE TABLE IF NOT EXISTS certificate_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  storage_url TEXT NOT NULL,
  text_positions JSONB NOT NULL DEFAULT '{}',
  is_active BOOLEAN NOT NULL DEFAULT false,
  uploaded_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
 
-- Settings table (key-value store for platform config)
CREATE TABLE IF NOT EXISTS settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL DEFAULT '',
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
 
-- Seed default certificate template settings
INSERT INTO settings (key, value)
VALUES ('certificate_template_url', ''), ('certificate_text_positions', '{}')
ON CONFLICT DO NOTHING;
 
-- Ensure certifications table has revoked_at column
ALTER TABLE certifications ADD COLUMN IF NOT EXISTS revoked_at TIMESTAMPTZ;
 
-- RLS: allow anon reads on certifications (active only) for public registry
ALTER TABLE certifications ENABLE ROW LEVEL SECURITY;
 
CREATE POLICY IF NOT EXISTS "Public read active certifications"
  ON certifications FOR SELECT
  TO anon
  USING (status = 'active');

4.2 Survey System
-- Survey definitions table
CREATE TABLE IF NOT EXISTS surveys (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  type TEXT NOT NULL CHECK (type IN ('pre_course', 'post_course')),
  is_active BOOLEAN NOT NULL DEFAULT false,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
 
-- Survey questions table
CREATE TABLE IF NOT EXISTS survey_questions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  survey_id UUID NOT NULL REFERENCES surveys(id) ON DELETE CASCADE,
  question_en TEXT NOT NULL,
  question_zu TEXT NOT NULL DEFAULT '',
  question_type TEXT NOT NULL CHECK (question_type IN ('multiple_choice', 'scale', 'free_text')),
  options_en JSONB,
  options_zu JSONB,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
 
-- Survey responses table
CREATE TABLE IF NOT EXISTS survey_responses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  survey_id UUID NOT NULL REFERENCES surveys(id),
  question_id UUID NOT NULL REFERENCES survey_questions(id),
  driver_id UUID NOT NULL REFERENCES drivers(id),
  response TEXT NOT NULL,
  submitted_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
 
-- Seed the two default surveys
INSERT INTO surveys (type, is_active)
VALUES ('pre_course', true), ('post_course', true)
ON CONFLICT DO NOTHING;

4.3 Supabase Storage Bucket (Certificate Templates)
Run this in the Supabase dashboard under Storage → New Bucket:

• Bucket name: certificate-templates
• Public: Yes (certificates must be readable without auth)
• File size limit: 10 MB
• Allowed MIME types: image/png, image/jpeg

Or via SQL:

INSERT INTO storage.buckets (id, name, public)
VALUES ('certificate-templates', 'certificate-templates', true)
ON CONFLICT DO NOTHING;

7. WhatsApp Template Submission
Before the WhatsApp notifications will work in production, you must submit all six templates to Meta Business Manager and wait for approval (typically 24-48 hours).

The approved template copy is in docs/handover/16-WHATSAPP-TEMPLATE-SPEC.md in all three repos.

Critical rule: When entering template bodies in Meta Business Manager, the portal base URL (https://betterdriver.co.za/portal) must be typed as static text in the template body - not wrapped in a {{variable}}. Only the unique token or driver name is passed as a variable.
